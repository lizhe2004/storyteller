# 音色多年龄适用范围设计

## 背景

当前角色年龄是单值，但 `VoiceConfig.age` 也被建模为单值。这无法表达一个音色同时适用于多个相邻年龄段的情况，例如儿童/少年、少年/青年或青年/中年，导致候选池和匹配排序丢失信息。

## 目标

- 让每个音色声明一个或多个适用年龄段。
- 角色年龄继续保持单值。
- 角色年龄只要包含在音色适用年龄数组中，就允许匹配。
- 保持已有项目文件、provider 目录和 API 数据的向后兼容。
- 前端、CLI、WebSocket 和 LLM 匹配上下文都能正确表达多个适用年龄。

## 非目标

- 不改变角色年龄的推断方式。
- 不把角色年龄改成数组。
- 不重新设计性别、分类、描述等音色属性。
- 不在本次改动中加入人工匹配反馈或训练数据存储。

## 数据模型

保留字段名 `age`，但音色的值改为字符串数组：

```json
{
  "provider": "mock",
  "voice_id": "child_teen_01",
  "age": ["child", "teen"]
}
```

角色仍使用单值：

```json
{
  "id": "fox",
  "age": "teen"
}
```

允许的音色年龄段沿用现有枚举：

```text
child, teen, young_adult, middle_aged, senior
```

年龄标签的中文展示沿用现有映射：儿童、少年、青年、中年、老年。

## 兼容策略

所有进入核心模型的音色数据都经过统一规范化：

- `"age": "child"` 转换为 `["child"]`。
- `"age": ["child", "teen"]` 保持数组并去重。
- 缺失、空值或未知值转换为空数组或被过滤，不抛出不可恢复异常。
- 新写出的项目 JSON、事件 payload 和 provider 数据统一使用数组形式。

统一规范化逻辑应位于核心数据模型或共享解析边界，provider 不应各自实现一套字符串/数组判断。

空数组表示“未标注适用年龄”，不应被当作所有年龄都匹配；现有兜底候选逻辑可以继续工作，但不能把未标注误当成精确年龄匹配。

## 匹配规则

角色年龄为 `character_age`，音色适用年龄为 `voice_ages`。

有年龄要求时，精准年龄匹配条件为：

```python
character_age in voice_ages
```

示例：

| 角色年龄 | 音色年龄 | 结果 |
| --- | --- | --- |
| child | child, teen | 匹配 |
| teen | child, teen | 匹配 |
| young_adult | teen, young_adult | 匹配 |
| middle_aged | young_adult, middle_aged | 匹配 |
| senior | young_adult, middle_aged | 不匹配 |

候选排序保留现有性别、偏好、分类和描述逻辑，并增加年龄精度排序：

1. 性别完全匹配优先。
2. 年龄包含角色年龄的音色优先于年龄为空的音色。
3. 只覆盖一个年龄段的音色优先于覆盖多个年龄段但都能匹配的音色；这是软排序，不得排除多年龄音色。
4. 其它分类、名称、描述和角色偏好排序继续生效。

如果当前匹配器的候选池逻辑会因为数组字段改变而失效，应以“交集/包含关系”替换原有标量相等判断，同时保持无候选时的安全兜底行为。

## Provider 与数据目录

以下 provider 的音色目录需要统一输出数组形式，并保留对旧标量目录的读取兼容：

- Mock
- 阿里云
- 火山引擎
- OpenAI-compatible
- 其它复用 `VoiceConfig` 的 provider

现有单值目录可以继续作为输入，不要求一次性手工重写所有历史目录；经过规范化后，对外输出数组。

## API、CLI 与前端

### WebSocket

`characters_matched` 和 `script_ready` 中的音色对象返回：

```json
{
  "voice": {
    "age": ["child", "teen"]
  }
}
```

角色对象中的 `age` 仍是单值字符串。

### CLI

音色列表中的年龄列将多个年龄显示为中文连接文本，例如：

```text
儿童 / 少年
```

JSON 输出中的 `age` 使用数组。

### 前端

- 角色卡片继续展示角色自身的单值年龄。
- 音色浮层把音色年龄数组渲染为中文标签列表。
- 前端类型将音色 `age` 改为 `string[]`，必要时在兼容旧历史事件时接受字符串并归一化。

### LLM 匹配上下文

传给 LLM 的候选音色描述必须明确标出多个适用年龄，例如“适用年龄：儿童、少年”，避免 LLM 将数组误读为单一年龄。

## 测试要求

### 核心模型与兼容

- VoiceConfig 接收数组年龄。
- 旧字符串年龄被规范化为单元素数组。
- 空值和未知年龄不会导致构造或读取崩溃。

### 匹配器

- 角色年龄与多年龄音色存在交集时可以匹配。
- 不存在交集时不会作为精准年龄候选。
- 多年龄音色仍能参与兜底候选选择。
- 多年龄音色不会破坏性别和角色偏好匹配。

### Provider 与输出

- 至少覆盖一个 provider 的多年龄目录读取。
- WebSocket 事件返回数组年龄，角色年龄仍为单值。
- CLI JSON 和表格输出正确显示数组年龄。

### 前端

- 音色浮层显示多个中文年龄标签。
- 旧字符串事件在前端不会导致渲染错误（如果保留运行时兼容）。

## 验收标准

- 配置一个 `age: ["child", "teen"]` 的音色后，儿童和少年角色都能进入该音色候选。
- 青年/中年组合音色可以匹配青年和中年角色，但不能精准匹配老年角色。
- 旧的 `age: "child"` 数据仍能正常加载、匹配和生成故事。
- 页面浮层和 CLI 能清楚显示多个年龄范围。
- 现有前端测试、相关后端测试和构建全部通过。
